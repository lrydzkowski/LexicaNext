# Run LexicaNext with Docker Compose

Use `compose.standalone.yaml` to run the React frontend and .NET API in one
container, with separate PostgreSQL 15 and Seq containers. A setup container
applies database migrations before the application starts.

## Prepare configuration

Install Docker with Linux container support, Docker Compose, and the .NET 10 SDK.
Use your local Docker instance. From the repository root, change to the container
setup directory:

```powershell
Set-Location containers
```

Run the remaining commands from this directory. All image
builds use the repository root as their build context.

Copy the configuration template:

```powershell
Copy-Item .env.example .env
```

Edit `.env` and set `POSTGRES_PASSWORD`, `HTTPS_CERTIFICATE_PATH`,
`HTTPS_CERTIFICATE_PASSWORD`, `SEQ_ADMIN_PASSWORD`, `AUTH0_DOMAIN`, and
`AUTH0_AUDIENCE`. Set
`AUTH0_DOMAIN` to the Auth0 tenant hostname without `https://`. Use your Auth0 API
identifier as the audience.

The frontend build reads
`../Frontend/lexica-next-front/env-config/.env.production`. Edit that file to change
the frontend API base path or Auth0 domain, client ID, audience, and scope. Set
the backend's `AUTH0_DOMAIN` and `AUTH0_AUDIENCE` in this directory's `.env`
to match `VITE_AUTH0_DOMAIN` and `VITE_AUTH0_AUDIENCE` in the frontend file.

Use single quotes around values that contain `$` or `#`, such as
`POSTGRES_PASSWORD='a-long-random$value#with;punctuation'`. Use database names and
usernames containing letters, digits, and underscores. Shell environment
variables take precedence over `.env` values in Compose.

The default HTTPS port is `10051`. Change `APP_HTTPS_PORT` if that port is in use.
The default `APP_BIND_ADDRESS=127.0.0.1` restricts access to your computer. Set
`ALLOWED_HOSTS` to a semicolon-separated list of hostnames, without ports, to
restrict accepted host headers. Its default value is `*`.

`containers/.env` and `containers/certificates` are ignored by Git and excluded
from Docker build contexts. Keep private configuration in those locations.
Frontend Auth0 settings are public and become part of the JavaScript bundle.

## Configure a local HTTPS certificate

Export and trust a development certificate on the computer running Docker:

```powershell
New-Item -ItemType Directory -Force certificates
dotnet dev-certs https --trust -ep certificates/lexica-next.pfx -p "your-local-password"
```

Set `HTTPS_CERTIFICATE_PATH=./certificates/lexica-next.pfx` in `.env`. Set
`HTTPS_CERTIFICATE_PASSWORD` to the password you used when exporting the file.
The application mounts the PFX read-only. Relative certificate paths resolve
from this directory.

The message `A valid HTTPS certificate is already present` is normal when
reusing a development certificate. Check that the export exists:

```powershell
Test-Path certificates/lexica-next.pfx
```

New development certificates generated by .NET 10 include `127.0.0.1`. If you
reuse an older certificate that only covers `localhost`, use
`https://localhost:10051`. See the
[dotnet dev-certs documentation](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-dev-certs)
for certificate generation and export options.

In your Auth0 application's settings, add `https://127.0.0.1:10051` to Allowed
Callback URLs, Allowed Logout URLs, and Allowed Web Origins. If you use
`localhost` or a different port, add that address instead.

## Configure optional services

Fill in all five `FOUNDRY_*` values to enable AI translation and example sentence
generation. Leave them empty if you do not use those features. Set `API_KEY`
if you need API key access to endpoints that support it.

Keep the dictionary defaults to retrieve pronunciation recordings from
Cambridge. Recordings are saved in a named Docker volume. Adjust
`RATE_LIMIT_PERMIT_LIMIT` and `RATE_LIMIT_WINDOW` for different API request limits.

If your network requires an HTTP proxy, set `HTTP_PROXY` and `HTTPS_PROXY` in
`.env`. Keep `localhost,127.0.0.1,db,seq` in `NO_PROXY`. These settings apply to
image build commands and application HTTP requests. Image pulls use the daemon's
proxy settings. In the restricted Windows VM, use `http://10.0.0.1:3128` for both
proxy values and retain the existing firewall and Docker proxy configuration.
Compose also appends `db,seq` to the app's `NO_PROXY` value so container traffic
stays on the Docker network even if your shell overrides `.env`.

## View logs in Seq

Compose starts Seq 2026.1 and stores its data in the `seq-data` volume. After
starting the services, open `http://127.0.0.1:10052`. Sign in as `admin` with the
`SEQ_ADMIN_PASSWORD` you set in `.env`. Change `SEQ_PORT` if the port is in use.
Seq asks you to choose a new password at first login. The dashboard is bound to
your computer's loopback interface.

Keep `SEQ_SERVER_URL=http://seq:5341` so the app sends logs to the Seq container.
The ingestion port is available inside the Docker network without a published
host port. Leave `SEQ_API_KEY` empty for this setup. If you enable required API
keys for ingestion in Seq, create a key and set `SEQ_API_KEY` in `.env`.

Seq uses `SEQ_ADMIN_PASSWORD` only when it initializes an empty data volume.
To change the password for an existing instance, use Seq's user settings.
Changing `.env` does not reset an existing account's password.

## Build and start

Validate configuration without printing secrets:

```powershell
docker compose --env-file .env -f compose.standalone.yaml `
  -p lexicanext-standalone config --quiet
```

Build the images and start the services:

```powershell
docker compose --env-file .env -f compose.standalone.yaml `
  -p lexicanext-standalone up --build -d
```

Open `https://127.0.0.1:10051`, or your configured address and port.
PostgreSQL and Seq must become healthy, and migrations must succeed before
the application starts.
PostgreSQL has no published host port. The app and migration helper connect using
the Compose service name `db`.

Inspect service status and logs:

```powershell
docker compose --env-file .env -f compose.standalone.yaml `
  -p lexicanext-standalone ps -a
docker compose --env-file .env -f compose.standalone.yaml `
  -p lexicanext-standalone logs app migrate db seq
```

An exited migration container with exit code `0` is expected.
Check its logs if the application does not start. The `/api/status` endpoint
reports whether the API is running; it does not check database connectivity or
external services.

## Apply changes and stop

After changing `.env` or updating the source, rerun the build-and-start command.
Changes to frontend `env-config/.env.production` values require a rebuild.
Backend runtime settings are applied when Compose recreates the application
container. Use `up`, rather than `restart`, to apply configuration changes and
rerun migrations.

Stop and remove the containers while preserving all named volumes:

```powershell
docker compose --env-file .env -f compose.standalone.yaml `
  -p lexicanext-standalone down
```

Keep the same project name to reuse the named volumes. Changing `POSTGRES_DB`,
`POSTGRES_USER`, or `POSTGRES_PASSWORD` does not update an initialized PostgreSQL
volume. Update existing credentials in PostgreSQL before changing `.env`, or
reset the volumes if you intend to discard all existing data.

To permanently delete the database, recordings, and Seq data, add `--volumes`
to the shutdown command. The local certificate file remains on your computer:

```powershell
docker compose --env-file .env -f compose.standalone.yaml `
  -p lexicanext-standalone down --volumes
```
